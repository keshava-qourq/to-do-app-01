<!-- sdlc:auto:start overview -->
To Do app is a habit tracker, generated by the Quorq AI SDLC platform as two applications in one repository. The intended features are email/password auth, adding and deleting habits, a Today screen with tap-to-complete, and streaks. `frontend/` is a Vite + React 19 single-page app (TypeScript, Tailwind CSS v4, react-router-dom 7) whose approved screens still render seeded sample data. `frontend/src/lib/api.ts` provides `apiFetch`, the planned seam for wiring screens to the real API. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Pydantic 2. It currently exposes only `GET /health`, and no models or routers have been implemented yet. The backend uses SQLite (`./app.db`) by default and switches to PostgreSQL when `DATABASE_URL` is set. A `docker-compose.yml` provides a PostgreSQL 16 database for that purpose.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for the Vite/React frontend)
- Python 3.12 with pip (the backend Dockerfile uses python:3.12-slim)
- Docker with Docker Compose (optional: for the PostgreSQL 16 database and the backend container image)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd frontend && npm install
2. cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt   # Playwright's webServer expects the backend packages in backend/.venv
3. (Optional, to use PostgreSQL instead of the default SQLite file) docker compose up -d db   # from the repository root
4. cd backend && .venv/bin/uvicorn app.main:app --reload   # API on http://localhost:8000
5. cd frontend && npm run dev   # Vite dev server, which the backend's CORS defaults allow at http://localhost:5173
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- The frontend imports through the `@/` alias, which maps to `frontend/src/` (configured in vite.config.ts and tsconfig.json).
- Styling uses Tailwind CSS v4 via the @tailwindcss/vite plugin. Brand tokens live as CSS variables in src/index.css.
- Screens are built from the shared component and icon vocabulary in src/lib/ui.tsx and src/lib/icons.tsx.
- All HTTP calls should go through `apiFetch` in src/lib/api.ts. It prefixes `VITE_API_BASE_URL` (default http://localhost:8000) and sends a bearer token. The token is the session token stored in localStorage via `setSessionToken`, falling back to `VITE_API_SECRET_KEY`.
- Vitest component tests sit beside the components they cover (`src/**/*.{test,spec}.{ts,tsx}`). Playwright specs live only in `e2e/`.
- TypeScript runs in strict mode, but with `noImplicitAny` and `strictNullChecks` disabled.
- Code is formatted with Prettier and ESLint on the frontend, and with Ruff on the backend.
- Backend: one router per architecture component under app/routers/. Unimplemented routes return the typed `StubResponse` instead of raising.
- SQLAlchemy models inherit `Base` from app/database.py. Request handlers get a per-request session via the `get_db` dependency.
- There are no migrations yet: tables are created with `Base.metadata.create_all` in the FastAPI lifespan on startup.
- Backend configuration comes from environment variables: `DATABASE_URL` (default `sqlite:///./app.db`) and `ALLOWED_ORIGINS` (comma-separated, defaulting to the Vite dev origins on port 5173).

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The browser blocks API calls with a CORS error. | The backend only allows http://localhost:5173 and http://127.0.0.1:5173 by default. If the frontend is served from another origin (for example, the preview server on 4173), set ALLOWED_ORIGINS to that origin before starting uvicorn. |
| `npm run build` succeeds but `npm run typecheck` fails. | This is expected: `vite build` does not typecheck. Fix the reported types; the frontend README says these are usually untyped `useState({})` values read for named fields. |
| The build or dev server cannot resolve `@/App`. | main.tsx imports `@/App`, and the frontend README describes src/App.tsx and src/screens/, but neither appears in this file tree. Confirm the generated screens and App.tsx are present in src/. |
| Playwright fails to start the backend web server. | The e2e config runs `../backend/.venv/bin/python -m uvicorn`. Create backend/.venv and install requirements.txt into it first, as shown in setup_steps. |
| Playwright reports a missing browser executable. | Run `npm run test:e2e:install` in frontend/ to install Chromium. |
| `pytest` fails with `ModuleNotFoundError: app`. | Run pytest from the backend/ directory, where pytest.ini sets `pythonpath = .`. |
| Data is not going to PostgreSQL. | The backend defaults to SQLite (./app.db). Start the database with `docker compose up -d db`, then set DATABASE_URL to a SQLAlchemy psycopg URL that matches the compose credentials, for example `postgresql+psycopg://app:app@localhost:5432/app`. |
| `docker compose up` fails because port 5432 is already in use. | Stop the local PostgreSQL instance that is using port 5432, or change the host port mapping in docker-compose.yml and update DATABASE_URL to match. |
| Screens show sample data, and changes are not saved. | This is expected: the screens still render seeded data and the backend has only /health. Implement the backend routes, then replace sample data with `apiFetch` calls one screen at a time. |
<!-- sdlc:auto:end troubleshooting -->
